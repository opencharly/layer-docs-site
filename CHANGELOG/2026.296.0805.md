# 2026.296.0805 — fix(docs-site): re-pin DOCS_REF to the docs main head, and resolve the two corpus pages by name

Closes #8

## Summary

`DOCS_REF` moves from `f1c823b181e8316b20184f4b4d6dd8a495ff1e78` — the docs repo's `main`
head of 2026-08-24, **93 commits and two months stale** — to
`c5568310f0409676728f552712f0896359a789c5`, the docs repo's current `main` head
(`origin/main` at the time of writing). Both occurrences move together: the `var:` that
fixes the clone layer's cache key, and the literal in the `docs-site-pinned-commit` check's
`contains:` matcher, which the candy documents as a deliberate, non-collapsible
duplication (a check step's substitution does not resolve a candy `var:`).

Re-pinning it exposes a defect the stale pin was hiding, and this change fixes it too.

**The two corpus-projected page checks asserted paths the site stopped producing.** The
docs repo dropped the unversioned `reference/candy/charly.md` and
`reference/plugin/plugin-cdp.md` in its own #106 (`41b0b22`, 2026-08-31) and replaced them
with one page per corpus version, under a version-stamped directory
(`<repo>-<name>-v<calver>/`). The bed kept asserting the unversioned paths and stayed green
only because `DOCS_REF` still pointed at a docs commit from before that change — a stale
pin hiding a broken assertion.

Both checks now resolve their page **by name** and read the newest version, and each
**fails when no page exists at all** — a generator that narrowed to documenting nothing
would otherwise leave `cat` reading an empty path, and the check would pass on an empty
stdout. The assertions themselves are unchanged: a generated candy page still publishes its
Acceptance plan, and `plugin-cdp`'s page still renders its out-of-process placement and its
CUE parameter schema. A literal path would redden this bed on the next corpus advance — a
false alarm about a change that never touched the site.

The skill body (`/charly-tools:docs-site`) carries the same account, so it states how the
pages are located and why the unversioned paths are gone.

### The R1 RCA of that failure

**Mechanism.** The docs repo's own history, not this change, moved the pages. The unversioned
pages existed at the old pin and are absent at the new one:

```
$ git -C docs ls-tree -r --name-only f1c823b181e8316b20184f4b4d6dd8a495ff1e78 -- src/content/docs/reference/candy/charly.md
src/content/docs/reference/candy/charly.md
$ git -C docs ls-tree -r --name-only f1c823b181e8316b20184f4b4d6dd8a495ff1e78 -- src/content/docs/reference/plugin/plugin-cdp.md
src/content/docs/reference/plugin/plugin-cdp.md

$ git -C docs ls-tree -r --name-only c5568310f0409676728f552712f0896359a789c5 -- src/content/docs/reference/candy/charly.md
(no output)
$ git -C docs ls-tree -r --name-only c5568310f0409676728f552712f0896359a789c5 -- src/content/docs/reference/plugin/plugin-cdp.md
(no output)

$ git -C docs log --oneline --diff-filter=D --all -- src/content/docs/reference/candy/charly.md
41b0b22 chore(deploy): standalone plugin-docs generation + charly pin a31f76d7 (#106)
```

**Missed control.** Two, and both are the same defect seen from two sides. (1) The bed's
page paths were literals, never re-validated against the site's structure, so the site
could change shape under them. (2) Nothing tied the bed's fitness to a **current**
`DOCS_REF`: `docs-site-pinned-commit` proves the image holds *the pin*, never that the pin
is the docs repo's head. The control that would have caught the second — `task docs:pin`,
which compared `DOCS_REF` with the live docs head — was **deleted** in charly#452
(`665693b9`, 2026-08-29) with an explicit delegation to this repo ("charly cannot maintain
another repo's pin; that check belongs to layer-docs-site") and was never implemented here.
The guidance kept naming it anyway. That is filed as **opencharly/layer-docs-site#10**.

**Blast radius.** The bed has been green over two broken assertions since 2026-08-31 —
every run since the docs repo's #106 proved nothing about those two pages while reporting
PASS. The same literals would have reddened the bed on the next corpus advance for a
reason unrelated to what the bed asserts.

**Root fix.** In this change: the pages are resolved by name, the newest version is read,
and the absence of any matching page fails the check. The pin moves to the docs repo's
current `main` head, so the bed proves the site as it is published today, not as it was
published two months ago. The delegated currency control stays a filed obligation (#10):
it is a task in this repo, and it belongs to its own change.

**R5 — the legacy paths are gone.** The two literal paths are no longer asserted anywhere:

```

(no match)
```

(The skill body still NAMES those two unversioned paths, in the sentence that says they are
gone from the site — a statement about the past, not an assertion about the site.)
