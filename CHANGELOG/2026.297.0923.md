# 2026.297.0923 — feat(task): add the docs-pin report — the DOCS_REF control this repo owns

## Summary

The guidance named a control that did not exist. `task docs:pin` was delegated to this repo by
charly#452, which deleted the original implementation (`taskfiles/Docs.yml`) when the docs
candy moved out of the charly repo — the delegation was never taken up, so the five surfaces
that name it pointed at nothing. The `DOCS_REF` contract this repo's `AGENTS.md` states was
therefore unpoliced: nothing checked that the pin is the docs repo's current `main` head, and
nothing checked that the two occurrences of the sha in `charly.yml` agree
(opencharly/layer-docs-site#10).

This change implements the delegated control in the shape the issue's option (a) prescribes,
and in the shape the org pin contract draws: a pin that is BEHIND is an advance available NOW
in `opencharly/docs`, so it is REPORTED and stays green; a pin whose two occurrences disagree
is this tree contradicting itself, so it FAILS; a pin whose currency cannot be judged is a
FAILURE, because a gate that cannot judge is not a gate.

What lands:

- `scripts/docs-pin-report.sh` (new) — the report, in ONE implementation, with a `--self-test`

  argument, so the self-test drives every branch with a known value and nothing but git is
  stubbed. Each case asserts the state's own REPORT as well as its exit status: the `current`
  and `BEHIND` states both exit 0, so only the message tells them apart.
- `charly.yml` — the `docs-pin` task node (the control, over this repo's own sources), a new
  `check-docs` bed step that dispatches it on the host, and two comment corrections: the
  `DOCS_REF` var's comment and the `docs-site-pinned-commit` check's comment.
- `.agents/skills/docs-site/SKILL.md` — the five mentions of the retired identifier now name
  the control that exists, and the report's states are documented in a new section.
